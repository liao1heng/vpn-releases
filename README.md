## 首次使用

Windows首次打开输入管理员提供的服务密码，自动注册本设备。持有服务密码的人可以加入本服务，每台电脑仍使用独立密钥和配置；私钥只留在当前电脑。macOS仍需联系管理员完成设备登记。不要共用设备配置，也不要把私钥、设备配置或控制token上传到GitHub。

普通用户不需要服务器SSH账号或密码，管理员工具不随公开包提供。Windows按下面的双击流程操作即可。

## macOS arm64

在解压目录执行，配置目录必须已含本设备的 device.json：

```bash
sudo bash install-macos.sh "$HOME/Library/Application Support/personal-vpn" "$USER"
```

将“打开 Personal VPN.terminal”复制到桌面后双击。原生入口固定 Menlo 9pt、56列×9行；支持最小52×9。管理员完整升级会更新后台，界面文件可独立更新。安装保留已有设备、授权和白名单。

## Windows x64

1. 下载Windows ZIP，先完整解压，不在压缩包内直接运行。
2. 双击解压目录中的 **vpn.exe**。
3. 首次输入服务密码，等待自动登记；随后完成一次Windows管理员确认。
4. 客户端自动打开并准备白名单代理，空闲显示“按需待命”；访问白名单时才建立HTTPS代理连接。待命仅表示本机准备完成，不代表服务器已验证可用。

之后双击vpn.exe即可；新版本解压到新目录再双击，会自动准备升级并保留设备配置和白名单。取消管理员确认或准备失败时显示原因，可重新打开重试。无须自己运行PowerShell或复制device.json。

Windows桌面入口在准备完成后打开紧凑深色独立窗口（标题clean vpn），默认56×9字符格，约562×223像素再按系统缩放调整；标题栏、正文及边框同色，没有控制台滚动条。首次登记/升级准备阶段可能暂时显示命令窗口。关闭按钮或q只关闭界面，后台连接继续。升级前按q关闭旧界面，再双击新包vpn.exe；旧桌面快捷方式仍可能指向旧下载目录，请使用新包创建的快捷方式。显式终端命令vpn tui继续可用；vpn tui --desktop打开独立窗口。Mac原有入口、配色、字体和布局保持。

Windows无需开启或安装防火墙，程序不创建防直连规则，也不改变整机防火墙开关。受保护安装目录中的vpn.exe也可双击打开。

因为虚拟网卡和后台需要系统权限，这个入口会自动把运行文件放到Program Files\PersonalVPN，并建立本项目SYSTEM计划任务；配置保存在当前用户LOCALAPPDATA\personal-vpn。首次打开还会备份当前用户的系统网页代理设置，并启用本机 `127.0.0.1:1080` 代理。它不需要安装向导，但不是完全无系统改动的绿色版。首次准备所需权限仍须由用户确认，不会自动重启机器。Windows实际验收进度以版本说明为准，未实测项目不能仅凭构建保证。

## 服务密码与操作

首次打开由管理员提供固定服务密码，正确验证后168小时免输；重复打开不顺延有效期。到期不会中断已有后台连接及其自动恢复，下次打开、主动重新连接或后台重启后建立连接需再验证。验证页 Enter 提交、退格修改、Esc/Ctrl+C 退出；取消只关闭界面。

也可运行 `vpn unlock --home 配置目录`，从终端隐藏输入；不接受密码参数。密码错误、后台不可达或授权无法保存均不能通过验证。首次安装必须同时更新后台，旧后台不支持新的验证接口。

首页使用连接按钮，导航包含连接、在线、白名单、记录。q只关闭界面，后台继续；主动断开不自动重连。悬停导航/问号显示浮层，点击或键盘 m/? 固定，Esc收起；1–4切换面板。基础白名单从 GitHub 刷新，本机追加编辑 whitelist.custom.txt，一行一条；含#整行不加载。保存后点“重载TXT”，已有连接需重建。

白名单页将远端与本地域名数分行显示，并附最近成功获取/读取时间；本地指自定义追加，IP/网段另计，生效数按合并去重。重载时显示“远端加载中…”，按钮暂时变灰，完成规则应用后显示“远端加载完成”。远端失败明确显示“沿用缓存”，加载与失败期间保留上次有效规则；问号可查看原因。源时间未知不根据文件时间推测。摘要固定，方向键/滚轮只滚动规则列表；旧后台缺来源统计时需完整升级。

新版首页显示最近目标、观测时间、命中规则、预期与实际线路，以及尝试/发送/回传/失败。黄色最近异常单独保留，正常请求不会覆盖；点击异常或“分流记录”，也可在首页按f，查看最近5条已观察连接，↑↓/滚轮滚动、Esc返回。完整升级后台后才能提供这些证据，单独更新UI会提示升级。记录只在后台运行期间保留，重开界面不清除，后台重启清空；不保存完整网址路径或业务凭据。

“尝试中”不代表代理成功，“已观测回传”也不保证网页加载成功。程序无法观察完全绕过它的请求；仅IP且不能关联域名时预期显示未知。证据复用现有日志和本机查询，不增加公网探测；固定少量历史与关联上下文控制内存。

白名单支持以下格式混写，合并去重最多256条：

```text
example.com
*.example.org
142.250.0.0/15
8.8.8.8
```

IPv4单地址等价于/32；CIDR中的主机位会规范化。IPv6、默认全网段、本机/隧道保留地址及覆盖VPN控制地址的规则会被拒绝。旧版客户端无法加载网段，须用新包完整升级后台后重载TXT；仅更新界面不够。基础列表现包含40条域名与旧VPN的34条IPv4地址/网段，加入Google、ChatGPT及相关登录/静态资源域名。

## 网络行为与校验

只代理白名单域名和明确列出的IPv4地址/网段，其他目标保留原IPv4路径；不自动修改旧VPN、原DNS或hosts。网段按目标IP覆盖其中全部站点，包括共享CDN；只列网段不会为未列出的域名自动增加加密DNS保护。Windows新版保留系统IPv6和云主机网卡绑定，连接不检查外部IPv6路由。采用Windows系统代理的浏览器，HTTP/HTTPS外部目标经本机代理只使用IPv4，白名单经新VPN，其他网页经原IPv4路径。绕过系统代理的应用和协议不在此保证范围，系统本身仍可能使用IPv6。

白名单业务通过正式证书验证的HTTPS代理传输，目标网站的HTTPS证书仍由应用验证。取消后台心跳、隧道探测、保活、自动DNS诊断及在线/流量公网轮询；真实请求失败按其超时处理，空闲不向服务器无限重试。浏览器自身推送、WebSocket或后台访问仍属于应用业务，可能持续产生流量。

主动断开或核心退出后撤回本项目路由和域名规则，Windows直连IPv4网页代理仍由后台提供；白名单此时也使用原IPv4路径。代理服务器暂时不可达时，本机VPN核心仍可待命，下一次实际业务再尝试；不通过定时探测确认掉线或自动切换原路径。原连接及应用缓存可能需要重建，不能保证无缝切换。白名单DNS主备查询失败仍报错，避免错误解析。Windows后台停止时本机代理端口不可用，需重启后台或手动执行安装目录的 `web-proxy-windows.ps1 -Action restore` 恢复备份；新网卡、系统重启及原VPN共存按实际验收记录标明。域名规则仍有独立DoH、ECH、hosts及缓存等透明接管限制；未测项不保证完整覆盖。

空闲显示“按需待命”，首页以已观察分流证据替代旧质量指标。在线面板采用带时间的“最近活跃”快照，点击刷新时才获取；不通过心跳维持在线人数。后台启动使用缓存白名单，只在手动“重载TXT”时更新GitHub基础列表；DNS诊断只在点击检测时执行。新版本需完整升级后台，单独更新界面不能取消旧版心跳。

使用 PACKAGES.sha256 核对压缩包；包内 REVISION 是来源提交号。macOS在下载目录运行 `shasum -a 256 -c PACKAGES.sha256`；Windows用 `Get-FileHash 文件名 -Algorithm SHA256` 对照。第三方组件、许可证及固定上游源码地址见随包 THIRD_PARTY.md 和 sing-box-LICENSE。
